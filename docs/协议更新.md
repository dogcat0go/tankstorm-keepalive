# 协议更新

游戏换 SWF 之后，登录刚发出去就被服务器拆掉。把下面这段当作处理步骤，不要重新摸索 opcode。

## 怎么判断是这件事

日志里是「已登录」之后同一时刻 `连接中断: 服务器关闭连接` 或 `Connection reset by peer`，服务器一个业务包都没回。这是登录包的 opcode 过期了。

国家面板没打开、但连接还在，不是这件事。那种情况保持连接，国战助手停，保活继续。不要因为读不到国家就下线。

## 直接跑

在仓库根目录：

```bash
python tools/build_wiremap.py --latest
```

已经有 SWF 文件时：

```bash
python tools/build_wiremap.py RedWar_YYYYMMDDNN.swf
```

脚本会：

- 从 CDN `https://redwar-cdn.sincetimes.com/100616028/res/20120522/flash/RedWar_<版本>.swf` 取近 21 天里最新的一份。版本号是文件名里的数字，不是网页 FlashVars 的 `version`。这两个经常差一位，例如页面写 `2026092203`，文件是 `RedWar_2026092201.swf`。
- 按消息名把新 opcode 填进 `tankstorm/wiremap.json` 的新版本。
- 把这一版的 RC4 白名单写进该版本的 `exempt`，并同步 `tankstorm/crypto.py` 的 `EXEMPT`（给离线解密用）。
- 不改 `protocol.json`。

然后提交 `tankstorm/wiremap.json` 和 `tankstorm/crypto.py`。重启保活进程。登录时会用对照表里日期最大的那一版。页面版本比它新，日志会写「游戏页版本 … 比已适配的 … 新」。

## 成功时脚本会打印

- `写入 N 条 opcode`。N 比上一版少是正常的，叫不出名字的消息本来就不进表。
- 发送白名单 4 个、接收白名单 5 个。当前这版是发送 `046c 045e 04c0 0436`，接收 `02ae 02e6 0261 0292 0274`。下一版数字会变，个数不该变。
- `多出来的字段` 可以留着。解码不认识的字段会跳过。

跑完用下面这段核对登录帧。把版本换成脚本打印的那个。心跳必须变成白名单里的心跳 opcode，认证、加载同理：

```bash
python - << 'PY'
from tankstorm import protocol, wiremap
ver = wiremap.latest_version()
wiremap.ACTIVE = wiremap.for_version(ver)
spec = protocol.load_spec()
ctx = {"uid": "1", "secret": "s"}
frames = [data.hex() for data, _ in protocol.build_login_sequence(spec, ctx)]
hb = protocol.build_heartbeat(spec, ctx).hex()
print(ver)
print("\n".join(frames))
print(hb)
print("exempt", wiremap.ACTIVE.exempt)
PY
```

`a,{uid},{secret}` 和 TGW 头不要变。认证帧的 opcode 必须等于发送白名单里 RceInit 那一个，心跳帧的 opcode 必须等于 RceHeartbeat 那一个。

## 脚本失败时

按它打印的那一句处理，不要改登录包的十六进制。

- `关键消息没有进表`：`RceInit`、`RceLoad`、`RceHeartbeat`、`RceCountryOpen` 这类名字在新 SWF 里没对上。打开脚本看 `CRITICAL`。不要用上一版的 opcode 硬发。
- `不在发送白名单里`：注册表译出来的心跳/认证/加载，和 Transport 类初始化里的 `C2S_RceHeartbeat`、`C2S_RceInit`、`C2S_RceLoad`、`C2S_RceDebug` 不一致。以 Transport 里 `newarray` 收走的那组属性为准。
- `字段号对不上、已从对照表去掉`：这些消息本版不会发。被去掉的如果在 `CRITICAL` 里，脚本会直接退出。不要猜字段号。
- `白名单属性只有 …`：Transport 的类初始化里，`newarray` 前面连续 `getproperty` 的 `C2S_*` / `S2C_*` 就是白名单。值在同名属性的 `initproperty` 前一个 `pushshort`。`S2C_RseAuthState` 这种也是常量，但不在 `newarray` 里，不要放进白名单。

## 脚本靠的结构

混淆后的方法名每次都变，下面这些结构没变。脚本认结构，不认 `_-055` 这种名字。

- opcode 注册表在 `com.sincetimes.redwar.game.comnunicate.protocol` 里最大的那个方法，大约 567 次同一个 2 参调用。opcode 是 `add` 前面两个立即数之和，类是紧跟着的 `getlex`。
- 消息名来自字符串 `Bad data format: 消息名.字段名 cannot be set twice.`。类名本身不是 `_-` 开头的，直接用类名（`RceHeartbeat`、`RceCountryOpen`）。
- 本项目编号在 `tankstorm/schema.json`，键是 `2026101403` 那套。对照表只做「本项目编号 → 这一版线上编号」。
- 字段表沿用上一版。新字段号集合与旧的相同，或者只是多了字段，就继续用。否则这条消息不进表。
- 叫不出名字的空消息（大约 40 条）不进表。收到时记成 `8xxx`，要发时拒发。不要给它们补 opcode。

## 不要做

- 不要把 `protocol.json` 里的 `041c`、`041d`、`040e` 改成某一版的线上 opcode。那是本项目编号，`tankstorm/protocol.py` 在发送前翻译。
- 不要在没进对照表的版本上连上去碰运气。旧编号会被服务器当成别的消息，包括购买。
- 不要因为读不到国家面板就 `return 1` 下线。
- 不要用 `tools/extract_proto.py` 生成这份对照。它认的是旧 SWF 里的混淆方法名，新 SWF 上会得到 0 条 opcode。
